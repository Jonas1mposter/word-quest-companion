# WordMaster Grabber 1.16.0：DAC 防御分析

## 范围
仅静态读取用户提供的压缩包；没有运行扩展、调用其中的外部服务或使用其中的凭据。作者字段不能证明实际使用者身份，不据此处罚任何账号。

## 样本行为与本次加固
| 行为 | 原有缺口 | 本次处理 |
| --- | --- | --- |
| 直接调用 React onClick/onChange/onSubmit，伪造 nativeEvent.isTrusted | 不产生 DOM 事件，绕过窗口合成事件拦截 | 共享答题入口检查原生 Event、浏览器捕获记录、当前事件派发阶段及目标路径；普通对战选择、填空、原答案重试及旧答题卡均接入 |
| requestSubmit 程序化提交 | 浏览器生成 submit 不等于玩家主动答题 | DAC 监控中要求同轮真实点击或按键触发的表单操作 |
| 按函数源码筛选并删除 DAC 监听 | 指定监听器可被移除 | 关键答题和切屏监听改为 handleEvent 对象，抵抗此样本的函数签名过滤 |
| 随机化桥接 ID、属性与开关 | 固定 __tts_captured 标记失效 | 关联根节点随机交接前缀、同前缀版本与能力字段；单个随机属性不报，开启屏蔽时附加复核信号 |
| Proxy 包装 fetch/XHR/朗读等函数 | native code 字符串仍可能看似正常 | 不将原生字符串检查视为可靠证明；保留低置信度复核用途 |
| debugger 注入鼠标事件、焦点模拟 | 可能产生可信输入及可见状态 | 未声称能够在网页可靠区分；不能用窗口失焦、速度或插件痕迹单独扩大处罚 |
| REST 改写学习进度 | 进度写入不等于真实学习 | 本次未改学习权限或奖励算法；源代码中奖励仍使用 level_sessions，不以样本宣传推断其刷奖励成功 |

## 处罚和隐私
- 保留既有答题合成操作累计两次踢出规则；回调绕过尝试计入相同计数。
- 随机桥接和屏蔽开关仅记录复核，不自动封号、不单凭标记踢出。
- 既有 DAC 踢出整场排位作废、不消耗不掉分卡的服务器规则不变。
- 不读取、保存或上报隐藏桥中的词、答案、音频、令牌或扩展内凭据。

## 验证和边界
45 项针对性测试通过；隔离浏览器验证伪造填空回调、伪造提交回调及程序化 submit 均被阻止，真实输入和点击返回答对结果，页面无运行异常。检查到前端构建正常。

隔离页面不是已登录的真实对局，未验证线上端到端结算；外部 Supabase 无托管测试会话。本轮未发布，未更改数据库或部署云函数。网页无法保证阻止经过改造的主世界脚本、直接网络请求或浏览器级自动化。
