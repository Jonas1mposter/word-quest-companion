# Architecture rules
- Run team Boss membership, timed answer-then-action rounds, rescue, interruption and profile-locked capped payouts behind a service-role-only dispatch; authenticate callers in the team-boss edge function, expose only their issued question and preserve original-action retries so clients cannot change results or double-pay.
- Serialize match creation, timeout fallback and request-scoped cancellation through one transaction lock; persist cancelled search IDs, enforce one active match per human at insertion, and represent bots as server-owned null-slot metadata so friends stay together and bot games never enter rank settlement.
- Own temporary duo state in Dashboard through the shared lobby-party hook and render both players with the shared lobby card; gate grouped mode selection through partyRules and let only the ready host initiate the existing 2v2 matchmaking flow, so navigating away from the home view does not lose party synchronization.
- Route empty multiplayer settlements through a service-role-only match-row-locked RPC shared with grading; return no winner or benefits while atomically applying only the caller's forfeit penalty, so empty games cannot farm victories and retries cannot double-penalize.
- Observe online bans centrally in AuthProvider through verified profile reads triggered by Realtime, bounded fallback polling and reconnection; clear local auth state before sign-out and reject stale loads so open pages cannot retain access after a ban notification.
- Resolve general and category-specific leaderboard exclusions through server RPCs using stable profile IDs; apply the same shared grade scope to personal boards and reward ranking so category-only exclusions do not leak into other boards and displayed winners match settlements.
- Resolve achievement symbols through one presentation registry in the shared BadgeIcon, passing the original badge name at every achievement display; keep explicit upgrade families together and unrelated symbols unique without changing stored unlock rules or name-card icons.
- Gate startup on issued questions; bound reads, invalidate cancelled searches, isolate modes, restore server clocks and retry only the original answer with grading deduplication, so recovery cannot restart or corrupt battles.
- Monitor DAC absence only while online and healthy; distinguish actual hiding and surrender from automation evidence so network faults are not labelled cheating.
- Resolve listening recordings and speech fallback through a shared server-side audio provider with validated binary signatures; prefetch only issued audio and unlock Web Audio on user clicks so Safari async playback does not expose hidden answers or depend on AI quota.
- Keep final score-difference badge predicates in a server-shared module tested at inclusive boundaries; matching creates the per-player question sequence while the UI displays issued totals.
- Keep bot rewards service-role-only with ordered issued questions and profile-first atomic settlement; calculate base, perfect and Beijing-daily first-win bonuses there and return their breakdown. Never accept client payouts or auto-ban client reports.
- Reveal fill-in answers only through the submit response after checking the caller's persisted answer and issued question; never add answer fields to question payloads, so post-grade feedback cannot reveal unsubmitted or future questions.
- Keep visible-word playback fallback in the shared speech hook and use device speech after recording failure; never send hidden multiplayer listening answers to browser speech synthesis, so fallback cannot bypass question privacy.
- Keep administrative reward reversals transactional, batch-idempotent and backed by service-role-only before-state audit records; reverse only the targeted source batch so unrelated earnings survive.
- Keep reviewed UI translations and dynamic-message patterns in the shared localization layer; mark vocabulary content with data-no-translate so English UI never changes question meanings or answer choices.
- Keep multiplayer answers in service-role-only match secrets and persist each player's issued mixed-type question; server-only grading and authenticated opaque listening audio preserve ordering, idempotency and atomic scoring without exposing written answers or future questions. Maintain a choice-only compatibility path for older clients. Return listening bytes as application/octet-stream because Supabase FunctionsClient decodes audio MIME types as text and corrupts playback.

- Each lottery pool has its own draw RPC and progress row in lottery_progress; tickets bought in a pool carry lottery_pool_id and only work there, while untagged tickets work in any pool.
- Keep lottery event metadata in a shared event registry and expose each event on its own detail route; the lottery hall lists events without executing rewards, allowing more campaigns without coupling their prize pools.
- Interpret equipped badge slots as zero-based (0–2) across profile and shared battle cards; this keeps battle display aligned with stored equipment.
- Resolve ticket purchases, per-pool quotas and promotional pity inside transactional SQL using profile-first locks; UI reads server policy and progress so alternate draw entry points cannot bypass limits.
- Grant coins only server-side with Beijing weekend doubling; clients display returned amounts. Lock profiles for check-in to prevent concurrent duplicate claims.
- Learning rewards require single-use, server-timed level_sessions (start-level → complete-level); client durations and counts alone never unlock payouts.
- Run Halloween item battles entirely through hw_* SECURITY DEFINER RPCs over RLS-locked halloween_* tables (no client table access); serialize matchmaking with one advisory lock and settle once per match with a per-match reward ledger, so items, answers and capped bean payouts stay server-authoritative and never touch rank.
- Keep roguelike runs, issued questions, routes, skill offers and capped rewards server-authoritative behind caller-scoped rogue_action; serialize each player's actions, version-gate choices, deduplicate original answers and provide listening bytes through authenticated rogue-audio, so clients cannot alter progression or reveal unsubmitted answers.
- Detect browser-extension cheating in the shared DacBadge: extension injection and native tampering are only reported for manual review (benign extensions exist); only script-synthesized input/clicks forfeit, so innocent extensions are not punished.
